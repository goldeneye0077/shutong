# 核心网数通设备配置安全合规平台 PRD（AI 执行版）

## 1. 产品目标

本项目建设一套面向深圳试点的核心网及 5GU 数通设备配置安全合规平台，采用 `frontend`、`backend`、`data-service` 三域协同架构，覆盖资产台账、配置导入、异构解析、规则校验、巡检任务、问题闭环、报告导出和管理驾驶舱。

### 1.1 成功指标

- 关键检查场景自动化覆盖率 >= 95%
- 月度防火墙全量核查时长 <= 1 小时
- 日常事项处理效率提升 >= 50%
- 迎检资料准备周期缩短 >= 30%
- 问题发现到销项全流程可追溯

## 2. 用户与角色

| 角色 | 核心目标 | 主要触点 |
| --- | --- | --- |
| 运维人员 | 完成对象维护、配置导入、巡检执行和整改处理 | frontend、backend |
| 安全复核人员 | 审核高风险规则、例外审批和闭环复核 | frontend、backend |
| 审计/迎检支撑人员 | 快速获取问题清单、报告和迎检资料 | frontend、backend |
| 平台管理员 | 管理账号、角色、参数、审计和模板 | frontend、backend |
| 数据处理工作流 | 消费任务、解析配置、执行规则和生成报告 | data-service |

## 3. 范围

### 3.1 本期范围

- 首期对象：`CSW 10 台`、`BSW 4 台`、`OMSW 8 个`、`OMFW 8 个`
- 对象台账、配置文件导入、版本管理
- 多类型配置解析与标准化映射
- 规则库、自动校验、巡检任务、结果查询
- 整改派单、复核销项、例外审批
- 日志线索关联、问题清单导出、迎检资料包输出
- 驾驶舱与专题视图
- 本地账号/RBAC，预留统一认证适配
- AI 后置分析能力，占位不前置

### 3.2 非范围

- 首版不做设备自动下发配置
- 首版不将 data-service 暴露给 frontend
- 首版不引入 Redis、Celery、MinIO、外部云 AI 服务
- 首版不将 AI 分析结果作为最终结论直接下发

## 4. 关键流程

### 4.1 配置处理流程

1. 运维人员在 frontend 上传配置文件或导入台账。
2. backend 持久化文件、元数据并写入 `job_queue`。
3. data-service 认领任务，执行解析、标准化和规则校验。
4. backend 读取处理结果并提供查询接口。
5. frontend 展示配置版本、校验结果和问题清单。

### 4.2 巡检闭环流程

1. 运维人员创建临时巡检或平台按计划触发例行巡检。
2. backend 创建 `inspection_run` 和关联任务。
3. data-service 执行规则集并写回 findings。
4. 运维人员认领并整改，安全复核人员完成复核或驳回。
5. 闭环结果写入审计日志并进入报告统计。

### 4.3 报告导出流程

1. 用户发起问题清单、管理摘要或迎检资料导出。
2. backend 创建 `report_job`。
3. data-service 生成导出物并写入 `report_artifacts`。
4. backend 返回下载链接和状态。

## 5. 需求分组

### 5.1 Functional Requirements

- `FR-001` 到 `FR-006`：对象台账、导入、版本管理
- `FR-007` 到 `FR-011`：解析与标准化
- `FR-012` 到 `FR-017`：规则库与自动校验
- `FR-018` 到 `FR-022`：任务编排与结果分发
- `FR-023` 到 `FR-027`：整改闭环与例外管理
- `FR-028` 到 `FR-030`：日志支撑与告警关联
- `FR-031` 到 `FR-035`：报告输出与智能辅助
- `FR-036` 到 `FR-038`：可视化展示
- `FR-039` 到 `FR-042`：认证、权限、审计、参数配置

### 5.2 Non-Functional Requirements

- `NFR-001`：本地部署
- `NFR-002`：安全访问与导出留痕
- `NFR-003`：1 小时内完成月度核查
- `NFR-004`：失败重试与错误告警
- `NFR-005`：可扩展解析和规则体系
- `NFR-006`：端到端可追溯
- `NFR-007`：高频运维场景易用
- `NFR-008`：配置化、可维护

## 6. 三域归属

| 子系统 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| frontend | 页面、交互、主题、表格表单、任务状态轮询、下载入口 | 解析、规则执行、内部任务调度 |
| backend | 认证、RBAC、对象台账、流程状态、审计、上传元数据、公共 API | 配置解析、规则运行、报告生成核心计算 |
| data-service | 任务认领、解析、标准化、规则执行、报告生成、AI 分析 | 用户登录、审批 UI、前端接口直接暴露 |

## 7. 风险与约束

- 接口对接不确定性通过本地账号和文件导入兜底，不阻塞首版落地。
- data-service 与 backend 共库协作，必须严格划清表和状态变更边界。
- 规则与模板扩展采用配置化和版本化，否则后续推广成本会快速上升。
- 双主题必须从骨架阶段落实，避免后期样式返工。
