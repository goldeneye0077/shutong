# Frontend 用户故事

## 1. 页面目标

frontend 提供统一管理台，只消费 backend 的 `/api/v1` 接口，覆盖登录、导航、台账、导入、规则、巡检、问题闭环、报告导出和驾驶舱，并支持浅色/深色双主题。

## 2. 用户故事

### 2.1 运维人员

- 作为运维人员，我希望登录后直接看到与自己职责相关的菜单和对象列表，以便快速进入日常处理流程。
- 作为运维人员，我希望在资产与配置页面上传配置文件、查看版本差异和解析状态，以便确认配置是否已进入规则校验链路。
- 作为运维人员，我希望在规则与巡检页面发起临时巡检、查看例行巡检状态和执行结果，以便跟踪规则命中情况。
- 作为运维人员，我希望在问题闭环页面看到待处理问题、整改期限和复核意见，以便按优先级推进整改。
- 作为运维人员，我希望在报告页面下载问题清单和迎检材料，以便减少重复整理成本。

### 2.2 安全复核人员

- 作为安全复核人员，我希望查看高风险规则和高风险问题列表，以便优先处理重点事项。
- 作为安全复核人员，我希望在例外审批页面看到申请原因、依据和有效期，以便快速做出审批判断。
- 作为安全复核人员，我希望在整改复核页面对问题执行通过或驳回，并保留复核意见，以便形成闭环证据。

### 2.3 审计/迎检支撑人员

- 作为审计人员，我希望只读访问问题、报告和审计记录，以便快速查询资料而不影响业务数据。
- 作为迎检支撑人员，我希望基于模板一键导出迎检资料包，以便缩短应急准备时间。

### 2.4 平台管理员

- 作为平台管理员，我希望管理角色、参数和模板，以便控制系统边界和配置项。
- 作为平台管理员，我希望切换浅色和深色主题并保持用户偏好，以便提升长期使用体验。

## 3. 前端验收标准

- 登录后根据角色显示菜单，未授权页面不可见不可访问。
- 页面路由至少包含：驾驶舱、资产与配置、规则与巡检、闭环与报告。
- 所有列表页支持分页、筛选、空态和加载态。
- 上传类页面必须支持状态反馈、失败提示和结果刷新。
- 亮色/暗色主题在主布局、菜单、标题、表格和基础控件上表现一致。
- 下载型操作必须显示导出任务状态或结果反馈。
